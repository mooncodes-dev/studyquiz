# StudyQuiz 발표 개요

발표 흐름 8장 구성의 개요입니다. (발표: 가천대학교 오픈소스SW Group 46)

## 1장. 문제의식 — 왜 만들었나

- 시험 기간에 강의 자료 전체를 다시 읽는 데 시간이 너무 오래 걸린다.
- 요약만 읽으면 외웠는지 확인할 방법이 없고, 문제를 직접 만들기도 번거롭다.
- 그래서 "넣으면 요약과 문제가 나오는" 도구를 만들기로 했다.

## 2장. 목표와 설계 원칙

- 목표: 강의 자료 입력 → 요약 + 퀴즈 + 채점까지 한 번에.
- 원칙 1: **표준 라이브러리만으로 동작** — 설치 장벽 없이 어디서든 실행.
- 원칙 2: **오픈소스 활용은 선택적으로** — PDF 처리(pypdf)만 선택 의존성으로 분리.
- 원칙 3: 모듈 분리 — 추출/요약/퀴즈/채점/화면을 나눠 4명이 병렬 작업 가능하게.

## 3장. 전체 구조

- 데이터 흐름: 파일 → `extract` → `summarize`/`quizgen` → `grade` → CLI/웹.
- 모듈별 역할 표로 설명 (README의 프로젝트 구조와 동일).
- 핵심 알고리즘 두 가지:
  - 요약: 단어 빈도 기반 문장 점수(문장 내 핵심어 빈도 평균).
  - 퀴즈: 핵심 용어를 빈칸으로 가리고, 다른 핵심 용어를 오답 보기로 사용.

## 4장. 핵심 구현 포인트

- 한국어 간이 토큰화: 조사/어미 제거 규칙 ("프로세스는" → "프로세스").
- 객관식 보기 구성: 정답 1개 + 서로 다른 핵심 용어 3개, 순서 무작위.
- 채점: 객관식은 보기 내용 또는 번호로 답 가능, 빈칸형은 공백/대소문자 무시.
- 상태 없는 웹 데모: 퀴즈를 숨은 필드에 담아 채점 요청에 되돌려받는 방식.

## 5장. 데모 시나리오

1. 예제 강의(`examples/sample_lecture.txt`, 운영체제 개요 48문장)를 CLI로 요약.
2. 같은 파일로 퀴즈 5문제를 생성하고 `--interactive`로 직접 풀어 채점 확인.
3. 웹 데모(`python -m studyquiz.webapp`)에서 임의의 텍스트를 붙여 넣어
   요약과 퀴즈가 바로 생성되는 모습을 시연.
4. 단위 테스트 실행 결과를 보여 주며 검증 방식을 설명.

## 6장. 팀 역할 분담

| 역할 | 담당 |
| --- | --- |
| 요약 모듈 | 문장 분리, 토큰화, 추출 요약 |
| 퀴즈 생성 | 빈칸형/객관식 생성, 오답 보기 구성 |
| 웹 UI | 웹 데모와 CLI 화면 |
| 테스트·문서 | 채점 검증, 단위 테스트, README/발표 자료 |

- GitHub 협업 방식: 기능별 브랜치, `feat:`/`test:`/`docs:` 커밋 접두사,
  풀 리퀘스트 기반 병합.

## 7장. 검증 결과

- 단위 테스트: 요약(문장 수/출처/순서), 퀴즈(문항 수/정답 유일성/오답 구별),
  채점(만점/0점/부분 점수) 전 항목 통과.
- 예제 강의로 CLI 전체 흐름(요약 → 퀴즈 → 채점)과 웹 데모 동작 확인.

## 8장. 한계와 개선 방향

- 한계:
  - 추출 요약이라 새로운 문장을 생성하지 않는다.
  - 형태소 분석 없는 토큰화라 불규칙 어미에서 부정확할 수 있다.
  - 문서가 짧으면 핵심 용어가 부족해 문제 수가 줄어든다.
- 개선 방향:
  - TF-IDF 기반 점수화와 문장 간 중복 제거.
  - 형태소 분석기를 선택 의존성으로 연동.
  - 난이도 조절, 단답형/서술형 문제, 웹 UI 개선.
- 마무리: "설치 없이 바로 돌아가는 학습 도구"라는 목표 달성 여부로 정리.
